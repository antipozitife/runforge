## О проекте

Я сделала этот проект по тестовому заданию на позицию Junior Frontend Developer.
Это отдельное приложение на React, TypeScript и Vite, которое показывает список
запусков AI-агентов.

В интерфейсе можно найти нужный запуск, отфильтровать список по статусу,
отсортировать его по дате или длительности, а затем открыть подробности с логами
и результатом.

В качестве визуального референса я использовала
[runforge.sh](https://runforge.sh/). Оттуда взяла общее настроение интерфейса:
Inter, тёмно-синие акценты, тонкие границы и световые лучи. Светлые элементы
оформила в glass-стиле, а свечение сделала с переходом от синего к фиолетовому.

Сам интерфейс приложения полностью на английском языке.

## Что реализовано

- восемь демонстрационных запусков;
- статусы <code>Queued</code>, <code>Running</code>, <code>Succeeded</code> и <code>Failed</code>;
- поиск по названию запуска или репозиторию;
- фильтрация по статусу;
- сортировка по дате и длительности в обе стороны;
- сохранение поиска, фильтра и сортировки в URL;
- подробная информация о запуске в боковом диалоге;
- логи, результат и состояние ожидания результата;
- skeleton при загрузке;
- отдельные состояния ошибки и пустого списка;
- адаптивная вёрстка от 360 px;
- управление с клавиатуры и возврат фокуса после закрытия диалога.

## Запуск проекта

Для запуска нужны Node.js **22.12+** и pnpm **11.25.0**.

~~~sh
pnpm install --frozen-lockfile
pnpm dev
~~~

После запуска приложение будет доступно по адресу:

~~~text
http://127.0.0.1:5173/
~~~

На Mac также можно дважды нажать на файл **«Запустить Runforge.command»**.
Он запустит Vite, дождётся ответа сервера и откроет сайт в браузере.

Если удобнее использовать npm:

~~~sh
npm install
npm run dev
~~~

## Фильтры в URL

Поиск, выбранный статус и сортировка сохраняются в параметрах адреса. Благодаря
этому состояние страницы не теряется после обновления, а ссылкой можно поделиться.

| Параметр | Для чего нужен | Значения |
| --- | --- | --- |
| <code>q</code> | поисковый запрос | любая строка |
| <code>status</code> | статус запуска | <code>queued</code>, <code>running</code>, <code>succeeded</code>, <code>failed</code> |
| <code>sort</code> | порядок списка | <code>newest</code>, <code>oldest</code>, <code>longest</code>, <code>shortest</code> |
| <code>mock</code> | демонстрация ошибки | <code>error</code> |

Пример:

~~~text
http://127.0.0.1:5173/?status=running&q=web&sort=shortest
~~~

Значения по умолчанию не добавляются в URL, чтобы адрес оставался коротким.

## Структура

~~~text
src/
├── App.tsx                  основная страница
├── components/              компоненты интерфейса
├── hooks/useRuns.ts         загрузка и повтор запроса
├── hooks/useRunFilters.ts   фильтры и синхронизация с URL
├── services/                слой работы с данными
├── data/runs.ts             демонстрационные запуски
├── types/run.ts             типы данных
├── utils/runs.ts            поиск, сортировка и форматирование
└── styles.css               стили и адаптивность
~~~

Для этой страницы я оставила состояние в React hooks. Отдельный store и роутер
здесь были бы лишними. Получение данных вынесено в сервис, поэтому mock в будущем
можно заменить на настоящий API без изменения компонентов.

## Данные

Mock-сервис имитирует запрос списка запусков, отвечает с задержкой **650 мс** и
поддерживает отмену через <code>AbortSignal</code>.

Для проверки состояния ошибки можно открыть:

~~~text
http://127.0.0.1:5173/?mock=error
~~~

Первая загрузка завершится ошибкой, а кнопка <code>Try again</code> загрузит
обычный список.

Даты выводятся для часового пояса <code>Europe/Moscow (UTC+3)</code>. Если
длительность запуска неизвестна, вместо неё показывается <code>—</code>. При
сортировке такие записи всегда остаются в конце списка.

## Проверка

~~~sh
pnpm test
pnpm typecheck
pnpm build
pnpm preview
~~~

В проекте проходят **16 автоматических тестов**. Они проверяют:

- загрузку данных и все статусы;
- поиск и фильтрацию;
- сортировку по дате и длительности;
- синхронизацию состояния с URL;
- пустые состояния и обработку ошибки;
- открытие диалога с клавиатуры;
- закрытие по Escape и возврат фокуса;
- форматирование даты и длительности;
- отмену незавершённого запроса.

Также интерфейс проверялся в браузере на ширинах 360, 663 и 1440 px.

## Доступность

Я использовала нативные <code>button</code>, <code>input</code>,
<code>select</code> и <code>&lt;dialog&gt;</code>, добавила доступные названия и
заметный focus-state. Запуск можно открыть через Enter или Space, диалог
закрывается по Escape, а фокус возвращается на исходную строку.

Для пользователей с <code>prefers-reduced-motion</code> анимации отключаются.

## Ограничения

- реальный backend не подключён;
- данные хранятся локально и не меняются автоматически;
- статус <code>Running</code> не связан с настоящим агентом;
- кнопка <code>Refresh</code> повторно загружает тот же mock-набор;
- live-логи и авторизация не реализованы.

[AI_LOG.md](./AI_LOG.md). В архив не попадают <code>.git</code>,
<code>node_modules</code>, <code>dist</code>, <code>.DS_Store</code> и
<code>__MACOSX</code>.
